Debezium - Toast - Missing updates

Smital Desai June 10, 2026

Problem: 

You have the CDC working fine and suddenly your downstream reports that it has not received updates on certain tables since last 20 days ....

RCA:

The table has a json column which suddenly increased in size ( huge polylines stored in this json attribute ) and hence the because of the eligibility started getting saved in Toast tables.

  • For tables with columns that are eligible to be stored in TOAST tables, by default, when an update occurs which doesn't touch the column (where data is present in toast table), the TOAST table data is not added to the WAL to optimize for WAL size.
    • This behaviour is controlled using a config called "replica identity" in postgresql
  • This causes the CDC to get an object where this column data is not present.
    • For our case, the column was "attributes" in route_activities table.
      • Same will be true for other tables having jsonb columns
    • Debezium by default sets such columns to the value of "__debezium_unavailable_value"

 

When such a WAL was ingested in internal service, JSON parsing of the "attributes" column failed, causing no kafka event to be published for this change.
